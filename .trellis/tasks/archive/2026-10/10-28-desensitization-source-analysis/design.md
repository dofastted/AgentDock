# 脱敏插件源码分析与打包设计

## 交付边界

分析当前仓库内置 `redact`，不开发新插件，不修改 `engine/` 或 `shell/` 业务源码。单一任务同时拥有技术说明和源码归档，两者共享同一源码快照与验证记录，不能独立验收，故不拆父子任务。

计划交付到 `deliverables/redact-analysis/`：

- `README.zh-CN.md`：阅读入口、目录、许可证、依赖和复现步骤。
- `TECHNICAL-ROUTE.zh-CN.md`：源码导读、架构/流程、识别和替换机制、JSON 与流式兼容、模型路线、宿主接入、限制与移植建议。
- `SOURCE-MANIFEST.sha256`：归档源码与资源逐文件 SHA-256。
- `verification.txt`：真实执行命令、环境、行为输出、测试和归档复核结果。
- `redact-source-and-roadmap.zip`：上述说明及按原始相对路径保存的源码/依赖/fixtures/许可证；不包含自身。

## 源码层次

1. **核心**：`engine/internal/redact/` 全部生产源码、现有测试和 testdata。
2. **插件与接口**：`engine/plugins/redact/`、`engine/internal/masking/`、`engine/internal/gwmw/` 和插件四个客户端资源。
3. **可验证依赖**：通过四个目标包的 `go list -tags nogui -deps -test` 解析本地闭包；收录生产依赖所需全部平台源码与资源，及目标测试需要的夹具。保留 `engine/go.mod`、`engine/go.sum`，不重写模块路径。
4. **集成参考**：网关脱敏/观测、GUI 隐私 API、设置和 provider 跳过策略等精确相关源文件及现有架构文档。清楚标注参考源码不是完整宿主，不能据此宣称全部网关/GUI 可独立编译。
5. **许可**：保留 `engine/LICENSE` 及确有需要的上游许可说明。模型权重不分发，单独说明其许可与下载边界。

## 技术分析结构

- 注册和启停：`plugins/redact` → `pluginrt` → `gwmw.Mask`。
- 配置与请求：设置 → `masking.Masker` → `redact.Options` → JSON/文本匹配。
- 核心机制：规则/用户词/已知值/可选模型、保护范围、重叠决策、mask/warn/block 与 allow、稳定占位符或保形替换。
- 响应机制：内存反向映射、JSON 还原、SSE 分块状态机、签名/工具协议边界。
- 安全边界：仅覆盖经该网关且实际进入脱敏路径的数据；失败关闭与用户明确放行分开说明。原值映射不落盘并不意味着哈希密钥不落盘。
- 复用路线：先复用算法和契约，再按宿主需要接入配置、模型、网关、观测；区分现成能力与建议步骤。

## 数据与打包契约

- 来源：磁盘实际源码优先，图只用于定位；每项关键结论给原始 `engine/...:line`。
- 保留字节：不格式化、不去掉测试、不替换源文件中已有内容。若发现源码原本含占位符或样例替换，记录现状，不“修复”来源。
- 打包：显式允许路径；排除运行凭据、`.env`、`settings.json`、`redact.key`、真实请求日志、模型缓存、编译产物、依赖目录、Git/Trellis/代理配置。
- 完整性：所有源码成员与来源逐文件对比长度和 SHA-256，拒绝绝对路径、`..`、重复 ZIP 成员和未声明文件；清单不含 ZIP 自身，避免自引用哈希。
- 复现：第三方依赖通过 go.mod/go.sum 解析，不 vendor；离线且依赖未缓存时不能承诺运行。

## 验证与风险

- 当前 Go 工具链已确认是 `go1.26.8 linux/amd64`，与 go.mod 一致；根 README 的 Go 版本不能作为验收依据。
- `MAGPIE_EVAL_CACHE` 会触发本地模型重录，验证必须取消该变量；不下载大模型、不使用真实个人信息或密钥。
- 临时 `go run` 示例使用合成密码/邮箱：实际 Mask → Restore、MaskJSON → RestoreJSON、SSE 跨事件还原；检查 warn/block 的归属，不把核心检测等同于网关拦截。
- 对原仓库和解包结果运行四个目标包现有测试；按研究结论选择必要网关 fail-closed 用例，不将未运行内容标为通过。
- 输出只新增交付目录和本任务规划/研究资料，撤销时移除本任务新增交付即可；无业务行为回滚。
